## Root cause findings (coordinator)
- Server facets (`query`, scripts/wal-index.ts:513-520) are built only from the acquired `ixs`; every WAL on disk
  (186 checked) holds only rows of its own session_id. Client replaces `agents` on each first page (useEvents.ts:88),
  guarded by `qgen`. So agents can only leak through ids the user can't see in the pick: the sidebar's filters hide
  picked rows (Sidebar.tsx:37 filterRows, count "N picked") and a stored pick from an earlier visit is restored
  (usePick.ts). That half is fixed by unit 1.1 (selected pinned on top, chips, newest-session default).
- Real leak in this unit: `tools` and `events` facets only `grow` (useEvents.ts:14,85-86) and never reset on a pick
  change, so tool/event chips keep values from deselected sessions. Category chips list all CATEGORIES regardless.
- Stale tool/event/cat selections are never pruned (only agents are, EventsTab.tsx:165-168).
- Empty pick: server `acquire([])` → no rows. Must mean all sessions.
