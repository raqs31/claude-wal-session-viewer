## Diagnosis (unpredictable selection)
1. lib/pick.ts:25 toggle refuses to unpick the last session: a click on the only checked row does nothing.
2. usePick re-runs reconcile on every 5 s poll (new `sessions` array); its newest-fallback (lib/pick.ts:17-19) re-picks a session the user did not choose whenever the pick empties (stream-reported unknown ids, vanished sessions).
3. groupByProject (lib/sidebar.ts:36-49) re-sorts rows and groups by `last` on every poll; live sessions jump under the pointer, so a click lands on a different row than aimed at. Main cause with live sessions.
4. Cross-tab `storage` sync (useStoredJson) lets another tab's stale reconcile overwrite this tab's pick; rapid toggles can ping-pong between tabs.
Fixes: allow empty pick; fallback only at page open; freeze row order while the pointer is over the list; pick is in-memory state (decision 2 ignores the stored pick anyway, so persistence only served the cross-tab sync).

## Contracts
### a. lib/pick.ts
- Keep `newest` (pick.ts:6-10) and `samePick` (pick.ts:22) unchanged.
- Replace `reconcile` with `prune(pick: readonly string[], sessions: readonly SessionMeta[], drop: readonly string[] = []): string[]` = dedupe pick (first occurrence order), keep ids listed in sessions and not in drop. NEVER falls back: may return [].
- `toggle(pick, id)`: remove if present (may yield []), else append. Delete the "refused" comment.
- Delete `isIdList` (no other user after chunk c).
- Tests: prune keeps stored order + dedupes; prune drops unknown/dropped ids and returns [] when all gone (regression: no newest fallback, e.g. prune([], rows) → [], prune(['x'], rows) → [], prune(['b'], rows, ['b']) → []); newest: most recent `last`, tie → first listed, skip set honoured, [] sessions → null; toggle(['a'],'a') → [] (regression), add/remove others. Remove isIdList test.

### b. lib/sidebar.ts
- `groupByProject(rows, lastOf: (r: SessionMeta) => number = (r) => r.last)`: use lastOf everywhere `r.last`/`a.last`/`b.last` is used for ordering and for `g.last`. Default keeps current behaviour exactly.
- New `pinPicked(rows: readonly SessionMeta[], pick: readonly string[]): { picked: SessionMeta[]; rest: SessionMeta[] }` — picked = rows whose id is in pick, in PICK order (ids not in rows skipped); rest = the other rows in input order.
- Tests: lastOf frozen map keeps row and group order stable when `last` changes between polls (reproduces the jump: same rows with updated `last` reorder under default, not under a frozen lastOf); unknown ids with lastOf→0 sink to the bottom; pinPicked order + skip missing.

### c. usePick.ts / App.tsx
- `usePick(sessions: readonly SessionMeta[] | null): { pick: readonly string[]; toggle(id: string): void; clear(): void; forget(ids: readonly string[]): void }`.
- State: plain `useState<string[]>([])` — no useStoredJson, no localStorage `wal.pick`.
- Effect on `sessions`: if null return; `const first = !opened.current; opened.current = true;` (ref set OUTSIDE the updater — updaters run lazily) then setPick(p => { n = first ? (newest(sessions) → [id] | []) : prune(p, sessions); samePick(p,n) ? p : n }).
- forget(ids): if ids.length && sessions !== null → setPick(p => keep-identity prune(p, sessions, ids)). clear(): setPick([]).
- useUnseen unchanged.
- App: destructure `clear`; pass `clear={clear}` to Sidebar. Render the Events/Sessions tab only once `rows !== null`; before that `<div className="empty">Loading sessions…</div>`. `ids` stays `rows === null ? NONE : pick` (array, empty = all).

### d. Sidebar.tsx / styles.css
- New prop `clear: () => void`.
- Rows: `<button type="button" className="sb-row" role="checkbox" aria-checked={on} onClick={() => toggle(r.id)}>` replacing label+input; native button gives Enter/Space. Trailing `<span className="ck" aria-hidden="true">✓</span>` on the right edge.
- Ordering: `rows = filterRows(...)`; `{picked, rest} = pinPicked(rows, pick)`; when picked non-empty render a first `<section className="sb-g">` with `<h2>Selected</h2>` and those rows (each with an extra project badge = group label from `all`); then `groupByProject(rest, lastOf)`.
- Order freeze: `.sb-list` onPointerEnter captures `new Map(sessions.map(s => [s.id, s.last]))` into state; onPointerLeave sets null. While set, lastOf = id → frozen.get(id) ?? 0. Pick changes still re-pin immediately (user decision).
- Chips in `.sb-top` after `.sb-n`, only when pick non-empty: per picked id a `button.chip.pk` (label = title || short(id), title attr full, aria-label `Deselect <label>`, trailing `×`) calling toggle(id), then `button.chip` "Clear all" calling clear. `.sb-n` text: `${shown}/${total} sessions · ${pick.length ? `${pick.length} picked` : 'all sessions'}`.
