### d. Contract
State model: `open` tracks "pointer is in the panel (React tree, so Sidebar's portaled tooltip counts) or the panel was opened from its trigger and focus/pointer has not left yet". It is no longer guarded by `pinned` (data-open is `pinned || open` anyway), so it is never stale when the user unpins.
- `const hover = useRef(false)`, `const id = useId()`.
- Trigger renders while `!pinned` (was `!pinned && !open`); it stays mounted under the open panel (CSS z-index 4 < panel 5), which also hides it whenever the panel is visible, `:focus-within` included (finding 3).
- Trigger (strip and handle) gets `onPointerLeave={(e) => { if (!(e.relatedTarget instanceof Element && e.relatedTarget.closest(`.panel[data-side=${side}]`))) setOpen(false) }}` — closes when the pointer sweeps off the trigger before the panel slides under it (finding 1, pointer case).
- Handle also gets `aria-expanded={open}`, `aria-controls={id}`, `aria-label={handleLabel}` (new optional prop `handleLabel?: string`). Handle onClick unchanged (flushSync open, focus arrow).
- Aside: `id={id}`; `onPointerEnter={() => { hover.current = true; setOpen(true) }}`; `onPointerLeave={() => { hover.current = false; setOpen(false) }}`;
  `onBlur={(e) => { if (!hover.current && !(e.relatedTarget instanceof Node && e.currentTarget.contains(e.relatedTarget))) setOpen(false) }}` — focus leaving the panel with the pointer outside closes it (finding 1, keyboard case).
- One why-comment each for: the trigger staying mounted under the panel (z-index), and the blur close.
CSS: `.panel-edge` and `.panel-handle` z-index 6 → 4, with a one-line why-comment (below the panel so a visible panel covers its own trigger); delete `.panel-edge[data-side=right]` (finding 4).
