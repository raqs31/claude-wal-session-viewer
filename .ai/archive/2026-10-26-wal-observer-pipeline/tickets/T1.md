## Context

Plan: `.ai/changes/wal-observer-pipeline/plan.md`, read "Implementation Approach" step 1, "Critical Implementation Details" (Torn tail, Single writer) and Phase 1.

Contract (copied from plan.md Phase 1 §1):
- `targetDir(source)` → `<config-dir>/wal-viewer`. `targetPath(source, id)` → `<dir>/<id>.jsonl`.
- `TargetRecord`: a discriminated union on `k`, covering every kind in "Implementation Approach" step 1 (`head`, `ev`, `call`, `tok`, `use`, `turn`, `compact`, `agent`, `tools`, `cost`, `ck`, `stale`). `TARGET_VERSION = 1`. `k` is the first key of every serialized record. `ev` writes `rec` (or `raw`) as its last key; `call` writes `input` then `response` as its last keys ("Search text").
- `appendRecords(file, records)`: writes whole lines in batches of at most 64 KB, like `appendLines` (`scripts/legacy.ts:25`). It writes a leading `\n` when the file ends mid-line.
- `createTargetReader(file)`: an incremental tail with `{ino, offset, carry}`. It returns the new records with their `off` / `len` in the target. It reports a shrink or new inode, and it skips unparseable lines.
- `acquireLock(dir)` / `releaseLock`: `<dir>/observer.lock`, holds the pid, created with `O_EXCL`. A lock whose pid is dead is replaced. Returns `false` when a live pid holds the lock.

Tests: `node --test` on a temp dir, no server. Cases: append, the torn tail, incremental read across a partial line, shrink and new inode detection, lock held / dead pid / released. Pattern for a temp-dir test: `scripts/legacy.test.ts`.

Do not commit; the orchestrator commits each phase after its review.

Decisions:
- Reader on a shrink or new inode returns `reset: true` and re-reads from byte 0 in the same call (like the index tail), so the caller drops what it built.
- Line `off`/`len` exclude the trailing `\n`, as `IndexEntry` does.
- `call.mcp` is a boolean (MCP tool or not); the plan lists the key without a type, and a call row has no request/response role.
- `ev.woff` is `number | null` and `ev.out?: number` exists: the plan's no-WAL turn rows have no WAL offset and carry `out` inline.
- `ck.wal` is `Pos | null` for a session without a WAL. `use` is `{k:'use'} & UsageRecord`.
- `tok` is two union members: `{tuid, out, res?}` and `{woff, out}`.
- The reader also skips a parseable line with no string `k`.
- `acquireLock` and `appendRecords` create the dir. A lock file with no valid pid counts as dead.
- The dead-lock takeover still has a small window if two servers race it. If the renamed file holds a different pid than the one read, the lock is put back and acquire returns false. A race gives false (no observer), not two holders.
- Follow-up 3 has no runtime test: it is a type-level change, checked by `npm run check`.
- Follow-up 4 has no new test: the partial-line read test covers the carry path.
