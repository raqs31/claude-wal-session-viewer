## Context

Source: T8.4 Follow-ups, 2026-10-26 16:23 (phase 4). The user's standing decision: fix all review findings and follow-ups.

1. Lineage bound. scripts/query.test.ts:421 checks `ms < 1500` for one timed run of 3000 rows of a 3000-deep chain (setup at :400-420). It measured 2312 ms at load average 24, with `matcher`/`lineageOf` unchanged. Fix: time the loop at :417-419 three times and take the minimum. Raise the bound to 5000 ms. Rename the label to match. Add one comment that says why: an O(depth²)-per-row regression costs about 3000 times more, so 5 s still catches it.
2. Purge deleting the target (scripts/wal-server.ts:262-276) is already tested at scripts/trash.test.ts:287 ('purge one deletes the target') and :298 ('purge all deletes the target of a --source session'). Both check `<config>/wal-viewer/<id>.jsonl` through `targetOf` at trash.test.ts:23. Do not edit trash.test.ts; verify runs it. Say so in the Result.
3. Orphaned server. `startServer` (scripts/test-server.ts:13) spawns `node wal-server.ts --port=0` with stderr inherited. live-tail.test.ts kills it only in the `finally` at :365. An uncaught exception skips that `finally`: for example a throw from `must`/`JSON.parse` in the `data` handler of `open` (:90-117), or a top-level await before the `try` at :120. The orphan then holds the inherited stderr, so `node --test` never exits. Fix in test-server.ts: after spawn, register `process.once('exit', () => server.kill())`. This covers every test file that uses `startServer` (discovery, live-tail, query, sessions, usage, trash). Also make `open` in live-tail.test.ts reject on a request `error`, so a refused connection fails the run instead of hanging it.

Tests: one manual proof in the Result only, no new test file. Temporarily add a throw in the live-tail `data` handler. Run `node --test scripts/live-tail.test.ts` and show it exits with no `wal-server.ts --port=0` left (`pgrep -f 'wal-server.ts --port=0'`). Revert the throw.
