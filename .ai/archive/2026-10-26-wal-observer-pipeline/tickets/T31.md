   - Change `:515` to `if (!r || r.hidden) return void res.writeHead(404).end('no such record')`.

2. Orphan targets (T17 follow-up, `scripts/wal-server.ts:385`). A target kept because `hold()` (`:85`) refused stays on disk after its session is purged; no server removes it later.
   - In `build` (`:285`), after the loop over `ids` in each tick: for each dir in `held` (`:81`), list its `<id>.jsonl` files whose name passes `validId`. An id is an orphan when it is in neither `discovery.list().sessions` nor `trash.list()` (`trash`, `:206`). Call `trash.list()` only when there is an orphan candidate.
   - For each orphan: `rmSync(<file>, { force: true })`, then `observer.drop(id)`, `indexes.drop(id)` and `store.drop(id)`, as `purge` does (`:386-388`).
   - A trashed session that is not purged keeps its target: it is in `trash.list()`, and a restore needs it.
   - Tests, in `scripts/observer-server.test.ts`. Extend the test at `:323`: after the purge through the reader, `until` the owner removes the target (`!existsSync(target)`). Add one test: a trashed, not purged, session keeps its target after the owner's next two ticks (wait 2500 ms, as `:375` does).
3. Root guard (T17 follow-up, `scripts/observer-server.test.ts:357`). The failed-append test fails under root, since root ignores `chmod 0444`. Give that test the option `{ skip: process.getuid?.() === 0 ? 'root ignores chmod 0444' : false }`.
