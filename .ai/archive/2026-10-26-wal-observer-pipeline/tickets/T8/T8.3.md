## Goal

`scripts/sessions.ts` keeps its API (`acquire`, `get`, `view`, `usage`, `drop`, plus `validId`, `parseScope` and the `Session` type), but builds each session from its target's records through `scripts/session-view.ts`. Its transcript parsers go. Every view and usage carries `pipe`.

## Non-goals

- No edit to `scripts/wal-server.ts` or `scripts/bench-sessions.ts` (siblings T8.4 and T8.8 update the call sites; until then `tsc` reports errors there and in `scripts/session-view.test.ts`, which is expected) or to `scripts/session-view.ts`.
- No sync inside the store: the server syncs before it reads.

## Context

Build on T8.1: read `scripts/observer.ts` for `Targets` and `pipeOf`, and `shared/api.ts` for `Pipe`. Build on T6: `scripts/session-view.ts` (`createSessionData` `:25`, `absorb` `:28`, `view` `:89`, `usage` `:103`). Plan Phase 4 §2 (copied): "The store keeps its API (`get`, `view`, `usage`, `drop`), but it reads target records through `session-view.ts`. Its parsers move into the observer. `version` is the target offset of the last transcript record read, so WAL rows do not resend views. It also changes when `pipe.stale` is set. `gen` changes when the store re-opens the target."

Design, settled:
- `createStore(targets: Targets, busy: (id: string) => boolean)` replaces `createStore(discovery, busy)` (`scripts/sessions.ts:43`).
- `export interface Session { id: string; gen: number; version: number; file: string; reader: TargetReader; data: SessionData }`.
- `load(id)` (`:107`): a cached session reads `s.reader.read()`; an uncached one gets `file = targets.target(id)` (null: drop it from `open`, return null, so `acquire` lists it in `unknown`), a new reader, `createSessionData()`, `gen = ++gen` (seed `Date.now()` as `:46`), `version = 0`, then reads. When `read()` returns `reset: true`, the session is re-opened: new `SessionData`, new gen, version 0, then the items. A missing target is a session with no data.
- Feed `absorb(s.data, items.map((i) => i.rec))`. `version` becomes the `off` of the last item read whose `k` is `use`, `turn`, `compact`, `agent`, `tools`, `cost` or `stale`. So `ev`, `call` and `ck` lines do not move it, and the `stale` record the observer appends moves it once.
- `acquire` (`:133`), `get` (`:146`) and the LRU (`:142`) keep their rules; `drop` (`:218`) stays.
- `view(s, scope)`: `view(s.data, { id: s.id, gen: s.gen, version: s.version }, scope)` from `session-view.ts`, null passed through, plus `pipe: pipeOf(targets.observer, s.id)`.
- `usage(ss, unknown)`: `usage(ss.map((s) => s.data), unknown)` from `session-view.ts`, plus `pipe` keyed by `s.id` with `pipeOf`.
- Remove `grow`, `discover`, `advance`, `records`, `recorded`, `agentStat`, `has`, `Tracked`, `Agent`, `CHUNK`, `pricing` and the imports they used. Keep `AGENT_RE` (used by `parseScope`, `:20`) and `validId` (`:18`, imported by `scripts/wal-index.ts` and `scripts/wal-server.ts`).
- Decision in force (T8 Comments): nested agents list spawner first, the order of the `agent` records (`scripts/session-view.ts:53`), not readdir order. That is intended.
- Update the header comment (`:1-3`). The grep in `verify` must print nothing, comments included.
