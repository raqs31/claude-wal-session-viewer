## Goal

`scripts/wal-index.ts` builds each session's index from its target, read through `createTargetReader`, instead of from the WAL. Each `ev` and `call` record is one entry. `createIndexes` takes `Targets` and keys its indexes by target path. `query` puts the server's `pipe` on the first page.

## Non-goals

- No edit to `scripts/wal-server.ts` (sibling T8.4 updates the call sites; until then `tsc` reports errors there, which is expected) or to any test file.
- No `tok` records (Phase 6): skip them like every other non-row kind.
- Keep `matcher`, `parentOf`, `lineageOf`, `ownerOf`, `agentTree`, `summary`, `cmp`, `vector`, `parseVector` and their semantics as they are.

## Context

Build on T8.1: read `scripts/observer.ts` for `Targets` and `shared/api.ts` for `Pipe`. Plan Phase 4 §1 (copied): "`tail()` reads the target through `createTargetReader` instead of the WAL. Each `ev` and `call` record becomes an entry. The virtual MCP pairing and the per-line derivation are removed, because the observer now does them. The read-time tree state (`agents`, `parents`, `about`, `links`) stays. `IndexEntry` keeps its fields, and `off` / `len` now point into the target. A call row has event `MCP call` for an MCP tool, else `Tool call`. Its cat follows the Post's cat. `day` / `minute` are derived from `t` at read time. `q` reads the source part of the target line, as in "Search text". `createIndexes` keys indexes by target path."

Design, settled:
- `createWalIndex(id, path)` (`scripts/wal-index.ts:89`): `path` is the target. `tail()` (`:207`) calls `read()` of one `createTargetReader(path)` (`scripts/target.ts:147`) per index. When `read()` returns `reset: true`, clear the index exactly as `:213-225` does now (new gen from `genSeed`), then add the items. Remove `indexLine` (`:129`), `WalLine`, `MCP_ROLE`, `pending`, `CHUNK`, `pos` and the raw read loop. A missing target is an empty index (the reader handles it).
- An `ev` item gives `{ off, len, t, day, minute, event: rec.event ?? undefined, cat: catOf(rec.event ?? undefined), tool, dur, tuid, agent, agentType, mcp, err, virtual: null }`. `cat` is recomputed with `catOf`, not read from the record, so targets written before the T8.1 `catOf` fix read right. `day` / `minute` as `:175-176`, from `new Date(t)`.
- A `call` item gives `event: rec.mcp ? 'MCP call' : 'Tool call'`, `cat: rec.err ? 'fail' : rec.mcp ? 'mcp' : 'tool'` (decision: keeps the `mcp` facet that the old virtual rows filled; failed calls count as `fail` like their Post), `t: rec.t`, `dur: rec.dur`, `mcp: null`, `err: rec.err`, and `tool`, `tuid`, `agent`, `agentType` from the record.
- `virtual` of a call entry: `{ pre, post }`, the seqs of the `ev` entries with the same `tuid` and event `PreToolUse` (pre) and `PostToolUse` / `PostToolUseFailure` (post), when both were indexed before it; else null. Keep a `tuid` map for this, cleared on reset, its entry deleted when the call is indexed, capped at `PENDING_MAX` (`:12`) by dropping the oldest key. The server's `/record` reads these seqs; `summary` (`:511`) already puts `virtual` on the row.
- Every other kind (`head`, `use`, `turn`, `compact`, `agent`, `tools`, `cost`, `ck`, `stale`, `tok`) is no entry.
- Tree state, for both `ev` and `call` entries: the `agents` rule of `:147-153` and `ix.tools.add(tool)`. For `ev` entries only, with `w = rec.rec` (the WAL line; absent on `raw` lines, and a transcript line on rows of a session without a WAL): the `parents` rule of `:155-161` (event `PostToolUse`, tool `Agent`, `w.payload.tool_response.agentId`) and the `about` rule of `:162-167` (event `SubagentStop`, `w.payload.background_tasks`). Read `w` defensively: it is untyped JSON.
- `push` (`:111`) stays: it inserts a call entry, whose `t` is the earlier Pre time, at its place in `order`.
- Search text (plan "Search text"): `reader(asc).text(r)` (`:265`) returns only the source part of the line: for a line that starts with `{"k":"call"`, from `"input":` to the end; else from `"rec":`, or `"raw":` when there is no `"rec":`, to the end. `serialize` (`scripts/target.ts:79`) puts `k` first and these keys last, and escaped quotes inside string values cannot match the unescaped key text. The window logic of `reader` stays.
- `createIndexes` (`:303`) becomes `createIndexes(targets: Pick<Targets, 'target'>, busy: (id: string) => boolean)`. `acquire(ids)` keeps its contract (null on an invalid id via `validId`; ids whose `targets.target(id)` is null go to `unknown`; tails every index it returns). The `open` map is keyed by target path; LRU eviction (`:325`) and `drop(id)` (`:330`) work by `ix.id`.
- `query` (`:540`) becomes `query(ixs, p, unknown, pipe: Record<string, Pipe>)`; the first page carries `pipe` as given. Pages after the first do not.
- Update the header comment (`:1-2`) and `IndexEntry` / `WalIndex` comments that name the WAL. The grep in `verify` must print nothing: no `.wal.jsonl`, `subagents` or `createParser` in this file, comments included.
