## Result

Landed: web/src/components/ConfirmDialog.tsx:1-89 (new component, native <dialog> + showModal); web/src/styles.css:1299-1359 (dialog.confirm, ::backdrop, list, skipped label, typed-yes field, actions, button.ghost.danger; only existing CSS variables, so light and dark both work).
Props: `ConfirmDialog({ title: string, confirmLabel: string, items: readonly ConfirmItem[], requireYes?: boolean (default false), onConfirm: () => void, onCancel: () => void })`, with `export type ConfirmItem = { name: string; skipped?: string }`. A set `skipped` is the label shown on the row (e.g. 'live', 'not ended') and marks the item as skipped.
Usage: mount it to open, unmount it to close: `{pending && <ConfirmDialog ... />}`. Escape and Cancel both call onCancel; the parent unmounts.
Check: `npm run check` exit 0; `npx biome ci web/src/components/ConfirmDialog.tsx web/src/styles.css` exit 0 (2 files, no fixes). Not exercised in a browser.
Decisions: mount-to-open instead of an `open` prop (no extra state, unmount closes the dialog in the effect cleanup). Escape's native cancel is preventDefault-ed so the parent stays the only owner of visibility. The header line reads "N to delete[, M skipped]" (N = items without `skipped`); items key is `name`, so names must be unique. Typed field matches `yes` after trim, case-insensitive; Enter in it submits only when it matches. Initial focus goes to the typed field when present, else Cancel. Confirm is not disabled when every item is skipped; callers (T17/T18) decide whether to show the dialog then. Skipped rows are muted with an italic label (not --status-warning, too low contrast on the light surface).
