## Goal

Check T11 for security: the write endpoints cannot be driven by another site, by DNS rebinding or by crafted request strings, and no request can make the server touch a path outside a session's own pieces.

## Non-goals

- Existing GET routes' lack of Host/Origin checks (out of scope per plan.md).

## Context

Decisions to hold the work to (plan.md Phase 4 §2, §4):
- Guard on every POST: method POST (else 405); `content-type` media type `application/json`, case-insensitive, before `;`; `Host` is `127.0.0.1:<port>` or `localhost:<port>` with `<port>` = `req.socket.localPort`; `Origin` equals `http://<Host>`; `Sec-Fetch-Site`, when sent, is `same-origin`; any failure → 403. Body over 1 MB → 413; bad JSON or shape → 400; any invalid id (`validId`, scripts/sessions.ts:18) → 400 for the whole request.
- Paths are built only from discovery's `Found` and the trash listing, never from request strings; restore and purge refs must match a current listing entry (else `unknown`). Look for traversal via `source`, `date`, `slug` in refs.
- Busy sessions are never moved; renames are same-filesystem, `EXDEV` → `failed` with rollback; purge never touches suffixed leftovers.
- Async POST handlers catch their own errors (the router's try/catch at scripts/wal-server.ts:310-317 sees only synchronous throws).
