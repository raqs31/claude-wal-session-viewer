## Goal

`scripts/trash.ts` does all filesystem work for trash, restore, purge and listing; `scripts/wal-server.ts` exposes `GET /trash` and the three POST routes behind the same-origin guard; `scripts/trash.test.ts` covers both through a real server on a temp HOME. plan.md Phase 4 §2, §4 (server part) and §5.

## Non-goals

- No `vite.config.ts` or README change (T12).
- No Host/Origin hardening of existing GET routes.
- No cross-filesystem copy fallback (`EXDEV` → `failed`, rolled back); no automatic repair of suffixed leftovers; no retention/expiry.

## Context

Builds on T10 (read its Result and shared/api.ts): `TrashRef`, `TrashEntry`, `TrashResult`, `SessionMeta.busy`, the discovery `Found` accessor, `indexes.drop`, `store.drop`, discovery's drop.

Trash module contract (plan.md Phase 4 §2, copied):
- "Trash dir per source: `dirname(projectsDir)/wal-trash/<YYYY-MM-DD>/<Found.slug>/`, holding `<id>.jsonl`, `<id>.wal.jsonl` (if any) and `<id>/` (if any). Date in local time."
- "`trash(ids)`: each id must be located by discovery (else `unknown`) and not live at that moment — checked as `busy` (else `live`, `reason: 'not ended'` when only the 24 h rule hit); a name already taken in the target dir → `conflict`; then the suffix-in-place, move, strip sequence in Critical Implementation Details. Errors (including `EXDEV`) → roll back completed steps, `failed` with the reason."
- "`restore(refs)`: each ref must match an entry of the current listing (else `unknown`); if discovery locates the id in any source, or any target name exists in `<projectsDir>/<slug>/` → `conflict`; recreates `<slug>/` if missing; mirror sequence with `.wal-restore`."
- "`purge(refs | 'all')`: recursive removal of the entry's pieces, then removal of now-empty `<slug>/` and `<date>/` dirs. Never touches suffixed leftovers."
- "`list()`: entries across all sources, newest date first; suffixed names ignored."
- "Paths are only ever built from discovery's `Found` and the trash listing, never from request strings."
- "Ids are processed independently; one failure never stops the batch."

Move order (plan.md Critical Implementation Details, copied): "Discovery lists a session by its transcript, so the transcript is the commit point. Trash: rename in place with suffix `.wal-trash` — transcript **first** (the session leaves the listing at once), then WAL, then `<id>/`; move the suffixed pieces into the trash dir; strip the suffixes — WAL and dir first, transcript **last** (the trash entry appears complete). Any failure undoes the completed steps in reverse. Restore mirrors it with suffix `.wal-restore`. Listings in both places ignore suffixed names." After a successful trash, call the T10 drops so the id reads unknown on `/events`, `/events-stream` and `/sessions`. Use `Found.slug` (raw folder name, worktree suffix included), never `SessionMeta.project.slug` (scripts/discovery.ts:327-331 strips it).

Routes and guard (plan.md Phase 4 §4, copied):
- "`GET /trash` → `{ entries: TrashEntry[] }`."
- "`POST /trash` `{ ids: string[] }`, `POST /trash/restore` `{ refs: TrashRef[] }`, `POST /trash/purge` `{ refs: TrashRef[] } | { all: true }` → `{ results: TrashResult[] }`."
- "Guard on every POST: method must be POST (else 405); `content-type` media type (before `;`, case-insensitive) `application/json` (a cross-site form can't set it without a preflight the server never answers); `Host` must be `127.0.0.1:<port>` or `localhost:<port>` with `<port>` = `req.socket.localPort` (`handle()` never sees the bound port, which may be 7878+n or ephemeral) (DNS rebinding); `Origin` must equal `http://<Host>`; `Sec-Fetch-Site`, when sent, must be `same-origin`. Any failure → 403. Body over 1 MB → 413; bad JSON or shape → 400."
- "Ids validated with `validId`; a bad id → 400 for the whole request."

Async in a sync router (plan.md Critical Implementation Details): `handle()` (scripts/wal-server.ts:181) is synchronous and the caller's try/catch (:310-317) only sees synchronous throws; the POST handlers read the body asynchronously and must catch their own errors and answer 500. Routes are an `if (url.pathname === …)` chain (e.g. :254 `/sessions`); `validId` is scripts/sessions.ts:18; server instances at :34 (discovery), :65 (store), :66 (indexes).

Tests in scripts/trash.test.ts through `startServer` (scripts/test-server.ts:13) on a `mkdtemp` HOME, as scripts/query.test.ts:16,135 does; use `node:http` `request` to set headers. One case each (plan.md Phase 4 §5): trash moves all three pieces and the session leaves `/sessions` and reads `unknown` on `/events`; a live session (fresh mtime) is skipped `live`; a session idle >2 min whose WAL does not end with `SessionEnd` is skipped with `reason: 'not ended'`; a name clash in trash → `conflict`; a forced failure mid-move (e.g. read-only target dir) rolls back so the session is still listed with all pieces; an `/events-stream` open on the session while it is trashed reports it unknown; restore brings it back and `/sessions` lists it; restore with the id present → `conflict`; purge one and purge all (empty `<slug>/` and `<date>/` removed); `/trash` lists across two sources (`--source`) and ignores suffixed files. Guard, each → 403 unless noted: missing `Origin`, foreign `Origin`, wrong `Host`, `Sec-Fetch-Site: cross-site`, `text/plain` body; GET on a POST route → 405; body over 1 MB → 413; bad JSON → 400; a bad id → 400. Rename failures by permission do not happen as root; skip that case with a message if `process.getuid?.() === 0`.
