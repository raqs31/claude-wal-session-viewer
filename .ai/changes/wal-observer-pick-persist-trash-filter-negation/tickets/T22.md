A toggle starts from what is shown. With nothing stored the newest session is shown and frozen (T3's major finding, fixed by T2): it must not jump when another session's `last` overtakes it.

Part 1 — effective(null) (source: T3 Follow-up 13:11, T1 Follow-up). - Delete `settlePick` (its only importer was usePick; `grep -rn settlePick web scripts` must come back empty).
- In `usePick`'s effect (web/src/usePick.ts:91-102) call `effective(wanted, sessions, gone, f)` for every case; drop the `wanted === null` special case at :98-99 and its comment at :96-97. Part 2 — stale closures (source: T2 Result Open, T3 Follow-up 13:07). `toggle` (web/src/usePick.ts:112) reads `pick` and `drop` (:114-119) reads `wanted` from the render closure; `pick` also trails `wanted` by one effect render, so two calls in one JS task lose the first. Fix with refs to the latest values:
- a `wantedRef` set wherever wanted is set (`adopt`, :70-73, which `save` goes through, and the initial state), read by `drop`;

- `toggle` and `drop` then depend only on `save`, so their identities stay stable. Keep `pick` state as the rendered value.
