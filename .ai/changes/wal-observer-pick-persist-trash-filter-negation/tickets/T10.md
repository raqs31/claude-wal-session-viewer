## Goal

Everything the trash module (T11) builds on: the shared trash types, `SessionMeta.busy`, `drop(id)` on the WAL index cache, the session store and discovery, and a discovery accessor for one id's `Found` plus busy state. plan.md Phase 4 §1 and §3.

## Non-goals

- No `scripts/trash.ts`, no routes, no guard (T11).
- No UI use of `busy` (Phase 5).

## Context

Contract (plan.md Phase 4 §1, copied):
- "`TrashRef { source: string; date: string; slug: string; id: string }` identifies a trashed session."
- "`TrashEntry extends TrashRef { title: string; cwd: string | null; size: number }` (title and cwd read the same way discovery reads them, from the trashed transcript)."
- "`TrashResult { id: string; status: 'ok' | 'live' | 'conflict' | 'unknown' | 'failed'; reason?: string }`."
- "`SessionMeta.busy: boolean` — `live`, or a WAL whose last event is not `SessionEnd` and `last` within the past 24 h (`OPEN_MS`, next to `LIVE_MS` in `discovery.ts`). A session idle at the prompt is not `live` but still open in Claude, which would recreate `<id>.jsonl` / `<id>.wal.jsonl` as a fragment after a trash. Sessions without a WAL fall back to `live`."

Contract (plan.md Phase 4 §3, copied): "`indexes.drop(id)`, `store.drop(id)` (or equivalent), a discovery accessor returning `Found` plus live state for one id without a full `list()` if practical. `acquire` serves an open index without `locate` and reads a missing file as empty (`wal-index.ts:206,314-316`), and the LRU skips busy ids, so `drop` must also remove busy/requested entries; the next `acquire` (including a stream's tick) then resolves through `locate` and reports the id unknown. Discovery drops the `heads` and `wals` entries for the moved paths (`heads` is otherwise never evicted, `discovery.ts:211`)." The accessor's state is `busy` (T11 skips busy sessions as `live`, with `reason: 'not ended'` when only the 24 h rule hit), so expose enough to tell live from not-ended.

Existing code: `SessionMeta` shared/api.ts:117 (`live` :134); `LIVE_MS` scripts/discovery.ts:17; `interface Found` :65 (not exported; T11 needs it); `createDiscovery` :160 with `where`/`misses`/`heads`/`wals` maps :161-165; `walk` :167; `locate` :200; `describe` :318 builds SessionMeta, `live` at :339 from `WalScan.lastEvent`; return object :383. `createIndexes` scripts/wal-index.ts:303 (`open` map, `acquire` :307, LRU sweep :325). `createStore` scripts/sessions.ts:43 (`load` :107, `acquire` :133). The server wires them at scripts/wal-server.ts:34,65,66.

Adding the required `busy` field breaks SessionMeta fixtures in web/src/lib/sidebar.test.ts, unseen.test.ts and pick.test.ts; add `busy` there (no other change to those tests).

Tests in scripts/discovery.test.ts (follow its existing temp-dir style), one assertion each: a live session is busy; a WAL without SessionEnd, `last` > 2 min and < 24 h ago → busy and not live; same WAL older than 24 h → not busy; a WAL ending in SessionEnd → not busy; no WAL → busy equals live; the accessor returns `Found` (source, slug, dir) for a listed id and null for an unknown one; after `discovery.drop` of a removed session the accessor/`locate` report it gone. Index and store drops are exercised end to end by T11's stream-during-trash test.

Never touch git state; the orchestrator commits per phase.
