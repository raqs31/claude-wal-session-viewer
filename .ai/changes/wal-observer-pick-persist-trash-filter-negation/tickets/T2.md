## Goal

`usePick` keeps the wanted pick in localStorage key `wal.pick`, adopts other tabs' writes via the `storage` event, derives the effective pick with T1's functions, and writes storage only on user intent; README documents it. plan.md Phase 1 §2 and §3.

## Non-goals

- No persistence of filter values (plan: filters stay unpersisted).
- No UI for trash; `drop(ids)` is added now but called in Phase 5.
- Do not change `useUnseen` (web/src/usePick.ts:42) beyond what the shared imports require.

## Context

Build on T1's exports in `web/src/lib/pick.ts` (read its Result). Contract (plan.md Phase 1 §2, copied): "return shape `{ pick, toggle, clear, forget }` unchanged, plus a `drop(ids)` used after a trash (user intent: removes ids from wanted and writes). `forget` only adds to the local gone set. `useStoredJson` cannot be reused as-is (it writes on mount and its fallback cannot be "absent"); either extend it with an opt-out of the mount write or keep the storage code local to `usePick`, whichever keeps the diff smaller."

Rules (plan.md Critical Implementation Details, copied): "Storage is written **only** on user intent — toggle, Clear all, and removing trashed ids after a trash — never by pruning, `forget`, the newest-session fallback or adopting another tab's value." "`pick` stays `null` until the first `/sessions` lands, so no query runs for all sessions before restore." A toggle starts from what is shown and writes the result.

Why this matters: the 2026-10-09 session-picker change removed a persisted `wal.pick` because cross-tab sync re-picked the newest session (`.ai/archive/2026-10-09-wal-session-picker/units/1.1.md`); the bug was derived state written back to storage.

Existing code: `usePick` web/src/usePick.ts:9 (caller App.tsx:43 destructures `{ pick, toggle, clear, forget }`), `useStoredJson` web/src/useStoredJson.ts:4 (also used by `useUnseen` at usePick.ts:43 — an extension must keep that caller's behaviour).

README: in "## The page" → Sidebar, replace "The page opens with the most recently active session picked" (README.md:106) with the restore, cross-tab sync and fallback rules (nothing stored → newest; stored `[]` → all sessions; all picked sessions gone → newest, not all).

Decisions: storage code kept local to usePick (useStoredJson untouched): it needs no mount write, an absent state and a fallback reset on adopt, so extending the shared hook would have been the larger diff. Storage events with a null/invalid value are ignored (keep ours), as useStoredJson does. A frozen fallback that is itself gone or unlisted is dropped and recomputed, else a dead id would stay shown forever (T1 returns a frozen fallback verbatim). drop(ids) with nothing stored (wanted null) writes nothing. forget dedupes and keeps the same array when it adds nothing, so App's forget(usage.unknown) effect does not churn. Review fix done in usePick, not pick.ts (T1's file, outside this ticket): for wanted === null usePick no longer calls effective, since effective(null) ignores its fallback argument; effective's null branch is now only exercised by T1's tests.
Open: toggle reads `pick` from its render closure, so two toggles fired in the same JS task (seen with two programmatic .click() calls in one evaluate) lose the first; real clicks re-render in between and were unaffected in 1.6.
