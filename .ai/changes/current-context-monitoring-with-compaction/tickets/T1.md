## Goal

On PostToolUse, PostToolUseFailure, Stop and SubagentStop the hook adds a top-level `context: { tokens, output, model }` to the WAL record: the size of the last API call of the agent that fired the event, read from the tail of that agent's own transcript. Covered by twelve new cases in the shell test suite.

## Non-goals

- No `context` on any other event (PreToolUse, PostCompact, SubagentStart, ...).
- No running max, no window percentage, no summing across lines.
- No change to `hooks.json` (all four events are already registered), the WAL index, or the viewer.
- No branch creation: work stays on the current branch `feat/subagent-prompts`. Do not commit; the orchestrator commits at phase end.

Contract (plan.md, copied):
- Events: `PostToolUse`, `PostToolUseFailure`, `Stop`, `SubagentStop`. Any other event: no read.
- Transcript choice, first match wins:
  1. `payload.agent_transcript_path` (string ending in `.jsonl`), as sent on SubagentStop.
  2. If `agent_id` is present: `<transcript_path minus ".jsonl">/subagents/agent-<agent_id>.jsonl`. `agent_id` must match `/^[A-Za-z0-9_-]+$/` before it is used in a path.
  3. Otherwise `payload.transcript_path`.
  (Note: `agent_id` and `transcript_path` may be promoted top-level fields of the parsed stdin; read them from `parsed`, not from `record.payload`.)
- Field: `context: { tokens: input_tokens + cache_read_input_tokens + cache_creation_input_tokens, output: output_tokens, model: message.model }`. Missing usage numbers count as 0.
- Omitted when: no qualifying path, file missing or unreadable, no qualifying assistant line within 4 MB, or any exception.
- Constraints kept: exit 0, nothing on stdout, exactly one `appendFileSync` per event. Synchronous fs only (`openSync` / `fstatSync` / `readSync` / `closeSync`), fd closed in a `finally`.
- Failure isolation: the context step has its own try/catch inside `main()`; a throw must never reach the outer catch, or the record is not appended.
- Tail window: read the last 64 KB; if no qualifying line is found and the window does not cover the whole file, widen x4 (256 KB, 1 MB, 4 MB) and stop at 4 MB, then omit `context`. When the window starts mid-file, drop the first (partial) line before parsing. Scan lines from the end and take the first that is `type === "assistant"`, has `message.usage`, and `message.model !== "<synthetic>"`.

Precedent for usage dedupe and the synthetic skip: `scripts/transcripts.ts:162-185`.

Tests: `plugins/wal-hook/hooks/wal-hook.test.sh`, helper `check()` at `:15`, cases start at `:31`. Write transcript fixtures into the scratch dir (WAL lands beside them). One `check` per case, exactly these:
- Two replies then a user line: `context.tokens` = second reply's sum; `context.output`, `context.model` from it.
- Same `message.id` on 3 lines with growing `output_tokens`: output from the last line, tokens not summed.
- Missing transcript file: record written, no `context`, exit 0.
- Transcript with no assistant usage yet: no `context`.
- Last assistant line is `<synthetic>`: `context` from the previous real reply.
- Last line a 300 KB user tool_result: `context` found by widening.
- Last line a 5 MB blob: no `context`, record still written.
- SubagentStop with `agent_transcript_path`: the agent file's context, not main's.
- PostToolUse with `agent_id` only: context from the derived `subagents/agent-<id>.jsonl`.
- PostToolUseFailure carries `context`; PreToolUse does not.
- `transcript_path` pointing at a directory: record written, no `context`.
- A context-bearing event writes nothing to stdout.

Decisions:
- When agent_id is present but fails /^[A-Za-z0-9_-]+$/ (or transcript_path is not a .jsonl), there is no context. It does not fall back to transcript_path, because that is the main transcript and would report the main agent's context for a subagent event.
- When the tail window starts mid-file and holds no newline, the window is treated as empty, so a fragment is never parsed.
- A directory as transcript_path: openSync succeeds and readSync throws EISDIR. The step's own catch handles it, so I added no isFile check.
- Several cases fold more than one assertion into one check string (e.g. "0 1 null" = exit code, WAL line count, context). This keeps one check per case, as the ticket asks.
