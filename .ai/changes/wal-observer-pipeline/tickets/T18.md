## Goal

`/events` filters by Total (`min_tok`, `max_tok`, `notok=include`) and, with `sort=tokens`, returns rows in Tokens order, paged (plan.md Phase 7 §1, §2). Add the query cases of Phase 7 §4 to `scripts/query.test.ts`.

## Non-goals

- No stream change (T19). No sort key other than Total. Without `sort`, nothing changes.

## Context

Plan: `.ai/changes/wal-observer-pipeline/plan.md`, read "Sorted pages with `q`", "Sort cursor" and Phase 7 §1, §2, §4.

Build on T16 (`IndexEntry.out` / `res` / `hidden`).

Contract (copied from plan.md):
- Filter (`matcher`, `scripts/wal-index.ts:471`): params `min_tok`, `max_tok` and `notok=include`, parsed with `num()` (`:353`). The filter applies only when a bound is set. Total = `out + (res ?? 0)` when `out` is set. A row with no `out` passes only with `notok=include`. The check goes before `q`. Same rules as the duration filter next to it.
- Order (`query`, `:540`): with `sort=tokens`, rows order by `(total, t, sess, seq)` descending, with `total = -1` for no data. `before` is `<total>.<t>.<sess>.<seq>` and matches `^(-?\d+)\.(-?\d+)\.([0-9a-f-]{36})\.(\d+)$`; `next` is built in the same form. Each page is one scan of the pick that keeps the top `limit` rows below the cursor. The first page still returns `total`, `counts`, `spans`, the facets and `pipe`. A `before` in the wrong form for the mode reads as no cursor.
- Sorted pages with `q`: on a page after the first, the scan applies the filter without `q`, sorts the rows below the cursor, and then tests `q` in that order until `limit + 1` hits. Only the first page runs `q` on every row.

Tests (through the server; fixtures are WALs plus transcripts with matching `tool_use_id`s): `min_tok` / `max_tok`, with and without `notok`; `sort=tokens` paged with `pageAll` (`scripts/query.test.ts:172`) against one full sorted list, with ties and no-data rows last; `sort=tokens` combined with `tool` and `q`; time order unchanged without `sort`.
