## Goal

The observer applies "Token rules" after each pass and appends `tok` records for call rows and Stop / SubagentStop rows; it keeps open calls and open Stops per session and retries them on every pass (plan.md Phase 6 §2). Add `scripts/tokens.test.ts` with the observer-level cases of Phase 6 §4. Then run manual check 6.4 on a copy of real data.

## Context

Plan: `.ai/changes/wal-observer-pipeline/plan.md`, read "Token rules", "Replay must not write", "Sessions without a WAL" and Phase 6 §2, §4.

Build on T14 (the parser data in `scripts/transcripts.ts`), T5/T10/T11 (`scripts/observer.ts`), T1 (`tok` in `TargetRecord`).

Contract (copied from plan.md):
- `tok {tuid, out, res?}` targets a call row; `tok {woff, out}` targets the Stop / SubagentStop `ev` at that WAL offset. The last `tok` per target wins.
- For a call whose `tool_use_id` is in reply R of agent A's transcript: N is the next distinct reply after R in A's file order. `prompt(x)` = input + cacheRead + cacheWrite5m + cacheWrite1h. Output: R.output, split over R's `tool_use` and `server_tool_use` blocks by `JSON.stringify(input).length`. Result: growth = prompt(N) − prompt(R) − R.output, split by the result size of each block. Splits round so that the parts add up to the whole.
- Result is omitted (Output only) when growth < 0 (compaction), when a user prompt (a non-tool_result user line) lies between R and N (an interrupted turn), or when N does not exist and the WAL has a `SessionEnd` after the call.
- N does not exist and the session has not ended: the call stays open, and no `tok` is written yet. A session without a WAL never ends, so its last open calls stay open. A `tool_use_id` in no transcript: no `tok` is ever written.
- Stop / SubagentStop: `out` is the output of the agent's last reply with `t` ≤ the Stop `ts`. That reply's last text block must start with `last_assistant_message` (with its `…[+N chars]` suffix cut). Until such a reply exists, the Stop stays open.
- A WAL row with `agent_id` joins against `subagents/agent-<agent_id>.jsonl`; with no such file, there is no `tok`. A `tool_use_id` found in more than one file uses the first file read.
- After a restart, the open-call set is rebuilt from the target (calls with no `tok` yet); replay writes nothing.

Tests (observer-level cases of plan.md Phase 6 §4), from the fixture transcripts (`scripts/fixtures/projects/`) plus hand-made WALs that copy their `tool_use_id`s: a single call; parallel calls split by input size and result size with parts adding up; streamed subagent replies use the final count; compaction gives no `res`; an interrupted turn gives no `res`; no next request: open while live, Output only after `SessionEnd`; a Stop matched by prefix, including a clamped `last_assistant_message`; a SubagentStop with no transcript file gives no `tok`; a `tok` across a restart without duplicates; an MCP call row gets a `tok`; a session without a WAL gets `tok` for its call rows and its Stop rows carry `out`.

Manual check 6.4, on a copy of real data, never in the real `~/.claude`: copy a real session with large calls (a WAL plus its transcripts) into a temp `HOME`, build its target with the observer, and check the Output / Result of at least three large calls by hand against the transcript's usage lines. Write the calls, the expected and the actual numbers in the Result. Put anything you could not check under `Open:` as an item for the user.
