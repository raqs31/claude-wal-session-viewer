## Goal

`createParser` in `scripts/transcripts.ts` exposes the data the token join needs, without changing today's outputs (plan.md Phase 6 §1). Add cases for the new data to `scripts/transcripts.test.ts`.

## Non-goals

- No join, no `tok` records (T15). No change to `UsageRecord` values, `aggregate` or any existing output.

## Context

Plan: `.ai/changes/wal-observer-pipeline/plan.md`, Phase 6 §1 and "Token rules".

Existing code: `createParser` (`scripts/transcripts.ts:115`) already merges streamed lines per `message.id` and collects tool ids (`:173-194`). `UsageRecord` (`:39`) has no tool_use ids, and items keep no result size.

Contract (copied from plan.md Phase 6 §1):
- Per reply: its tool_use / server_tool_use ids in block order, the input size of each, and the prefix of its last text block (2000 chars).
- Per tool id: its reply id and its result size, set when the tool_result arrives.
- Per reply: a flag for "a user prompt came after this reply". It is set when a non-tool_result user line follows the reply.

Definitions from "Token rules": input size is `JSON.stringify(input).length`. The result size is the length of the tool_result content: the string itself, or `JSON.stringify` of the blocks. A reply's lines can be split by other lines, so group them by `message.id`.

Tests: one assertion per clause above, plus one that existing outputs are unchanged (the current cases stay green unchanged). Copy the pattern of the existing cases in `scripts/transcripts.test.ts`.

Do not commit; the orchestrator commits each phase after its review.
