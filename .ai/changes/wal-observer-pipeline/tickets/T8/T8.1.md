- `export const syncBudget = (): number`: `Number(process.env.WAL_SYNC_BUDGET_MS)` when that env is set and is a finite number ≥ 0, else 150. Read on each call; comment that the env exists for tests only.
- `export const syncAll = (observer: Pick<Observer, 'sync' | 'state'>, ids: string[], budgetMs = syncBudget()): Record<string, Pipe>`: one deadline `Date.now() + budgetMs` shared by all ids, in order; each id gets `observer.sync(id, Math.max(0, deadline - Date.now()))`. A sync that throws is logged as `observer: sync <id>: <message>` with `console.error`, and that id gets `pipeOf(observer, id)`. Every id is a key of the result.

Contract 3, carried (a), the budgeted first sync (write mode only):
- Today a new session in `sync` (`:604-609`) runs `absorb(s, s.reader.read().items)` on the whole target at once, whatever `budgetMs` is.
- Change: in write mode, a new session absorbs its target in pieces. Add to `Session` the target byte offset absorbed so far and a flag that the absorb is not complete. Each sync, while not complete, reads the target from that offset with `lines()` (`:143`) under the same deadline the WAL pass uses (`now + budgetMs`, `:651`), and parses each line as `target.ts:137` does (skip a line that is not JSON or has no string `k`). It feeds the parsed records to `absorb` (`:224`), which takes `TargetItem[]`; build items with `off` and `len` as `createTargetReader` does (`scripts/target.ts:119`).
- The absorb is complete when `lines()` returns the target size, or returns the offset it started from (the rest has no `\n`: a torn tail). A missing target is complete at once.
- While it is not complete, `sync` returns `result(s)` (`:261`) and runs no transcript or WAL pass. Once complete, it runs the version check of `:608` and goes on with the pass in the same call, with the time left.
- A budget of 0 still reads one chunk per call (`lines()` checks the deadline after each chunk, `CHUNK` at `:23`), so repeated syncs always finish.
- `fresh()` (`:201`) at `:629` and `:640` makes sessions with nothing absorbed to do: they stay complete as today. The read-only path (`:611-621`) still uses `s.reader` unchanged.

The test of (a) is in sibling T8.5 (`scripts/query.test.ts`, server restart with `WAL_SYNC_BUDGET_MS=0`), and the test of (b) also. Here, `node --test scripts/observer.test.ts` must stay green with no test edit.
