## Goal

`scripts/wal-server.ts` runs one observer with `write: true`, syncs each request's sessions within the shared budget before it reads, syncs the streamed sessions on each tick, sends `event: stale` instead of `reset` for a stale target, answers `/record` from the target (call rows included), and deletes the target on purge.

## Non-goals

- No lock, no background loop, no `/observer` or `/rebuild` (Phase 5, T10).
- Do not edit `scripts/trash.ts`, `scripts/discovery.ts` or `scripts/legacy.ts`. If the work seems to need one of them, set the ticket `blocked` with the reason; do not edit it.
- No change to `/sessions`, to the empty-pick rule of `/events` (`:297-300`, sessions with `walSize > 0`) or to any test file (siblings T8.5-T8.7).

Plan Phase 4 §3 (copied): "Routes call `observer.sync(id, budget)` for their sessions before they read. `walTick` and `sessionTick` sync their streamed sessions before they read, so live latency stays at the 250 ms tick. `/record` reads the target. And: "When a streamed session's target turns stale, `/events-stream` sends `event: stale` with `{sess, reason}` once and no `reset`. `/session-stream` and `/usage-stream` carry it in `pipe.stale` of the next frame."

Design, settled:
- Setup (`:66-67`): `const observer = createObserver({ discovery, write: true })`, `const targets = { target: (id: string) => targetFile(discovery, id), observer }`, then `createStore(targets, …)` and `createIndexes(targets, …)` with the `busy` callbacks they have now.
- Sync order in every route: validate the ids first (`validId`, `scripts/sessions.ts:18`; 400 as now), then `syncAll(observer, ids)`, then acquire / get / read. `/events` and `/events-stream` (`:289`): sync the picked ids (or the empty-pick list), acquire, and `query(ixs, p, unknown, pipe)` where `pipe` holds the entries of `syncAll`'s result for the acquired `ixs` only. `/record` (`:329`): sync `[id]` first. `/session` (`:364`): sync `[id]`. `/usage`, `/usage-stream`, `/session-stream` (`:379`): sync `ids`.
- Tick (`:190`): before `walTick()` and `sessionTick()`, one `syncAll` over the union of the ids of `clients` (their `ixs`) and of `sessionClients`, so a session in both is synced once per tick.
- Stale on `/events-stream`: `Client` (`:47`) gains `stale: Set<string>`, filled at stream open with the picked ids whose `pipe.stale` is already set (the page has them from `FirstPage.pipe`). In `walTick` (`:137`), for each `ix` of a client whose `pipeOf(observer, ix.id).stale` is set and not in `client.stale`, write `event: stale\ndata: ${JSON.stringify({ sess, reason } satisfies StaleFrame)}\n\n` and add the id. No `reset` for this. The gen-mismatch `reset` (`:156-162`) stays for a target that is re-indexed.
- `/session-stream` and `/usage-stream` need no new code: the store moves `version` when the stale record lands, so `sessionTick` (`:101`) sends the next frame, and its view or usage carries `pipe`.
- `/record`: read the entry's bytes from `ix.path` (the target) and `JSON.parse` the target line. An `ev` line returns its `rec`, or for a `raw` line `parse(raw)` (`:38`), so `ev` rows keep today's shape. A `call` line returns `{ virtual: true, pre, post, call }` when the entry has `virtual` (`pre` / `post` = the `rec` of the target lines at `entries[virtual.pre]` / `entries[virtual.post]`), else `{ call }`. `call` is the parsed call line.
- `forget` (`:116`): also `observer.drop(id)`, so trash and restore drop the reader state and the next sync re-opens the target. The reset and unknown frames it sends stay.
- Purge (`writeOf`, `:239`): for `/trash/purge`, take `trash.list()` (`scripts/trash.ts:119`) before `trash.purge(...)` (`:200`). For each result with status `ok`, for each listed entry with that id, for each source in `discovery.sources()` (`scripts/discovery.ts:409`) whose `label` is the entry's `source`, `rmSync(targetPath(source, id), { force: true })` (`scripts/target.ts:18`); then `observer.drop(id)`, `indexes.drop(id)`, `store.drop(id)`. Purge is detected here only, not in `trash.ts`.
