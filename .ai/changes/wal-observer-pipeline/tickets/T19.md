## Goal

`/events-stream` sends `event: tokens` patches and, with a token filter, sends a row once its numbers make it match; a `sort=tokens` stream is refused (plan.md Phase 7 §3). Add the live cases of Phase 7 §4 to `scripts/live-tail.test.ts`.

## Context

Plan: `.ai/changes/wal-observer-pipeline/plan.md`, read "One seq space for patches", "Call row order" and Phase 7 §3, §4.

Build on T18 (`matcher` with the token filter, `scripts/wal-index.ts`) and T16 (hidden `tok` entries that patch their target row).

Contract (copied from plan.md Phase 7 §3): when the `walTick` scan (`scripts/wal-server.ts:137`) meets a hidden `tok` entry, it sends `event: tokens` with `[{sess, seq, out, res?}]` for the target row; with a token filter set, it sends the target row as a normal row frame if the row now matches but did not match without numbers. `tokens` frames have no `id:` line. The row frames' `id:` vector covers `tok` entries, so a reconnect replays them. A `sort=tokens` stream is refused with 400.

Tests: a call row arrives without numbers, then a `tokens` frame follows once the next request lands; with `min_tok`, the row arrives only after its `tok`, and only if it matches; a reconnect with `Last-Event-ID` before a `tok` still gets it; a late call row arrives with a `t` older than rows already sent; a `sort=tokens` stream gets 400.
