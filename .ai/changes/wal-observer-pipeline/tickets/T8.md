## Context

Why coupled: the index, the store and the server change their constructor contracts together (both get the observer and target paths), `shared/api.ts` gains `Pipe`, and the tests only run end to end through the server. The split puts the `shared/api.ts` and constructor contract first.

Plan: `.ai/changes/wal-observer-pipeline/plan.md`, read Phase 4 in full, "Search text", "Call row order" and "Single writer".

Build on: T3/T5 `scripts/observer.ts` (`createObserver({discovery, write})`, `sync(id, budgetMs)` → `{done, total, stale}`, `state(id)`, `drop(id)`), T6 `scripts/session-view.ts`, T1 `scripts/target.ts` (`createTargetReader`, `targetPath`).

Contract (copied from plan.md Phase 4):
- §1 `scripts/wal-index.ts`: `tail()` (`:207`) reads the target through `createTargetReader` instead of the WAL. Each `ev` and `call` record becomes an entry. The virtual MCP pairing and the per-line derivation (`indexLine`, `:129`) are removed. The read-time tree state (`agents`, `parents`, `about`, `links`) stays. `IndexEntry` (`:42`) keeps its fields, and `off` / `len` now point into the target. A call row has event `MCP call` for an MCP tool, else `Tool call`; its cat follows the Post's cat. `day` / `minute` are derived from `t` at read time. `q` reads the source part of the target line, as in "Search text". `createIndexes` (`:303`) keys indexes by target path.
- §2 `scripts/sessions.ts`: the store keeps its API (`get`, `view`, `usage`, `drop`) but reads target records through `session-view.ts`; its parsers move into the observer. `version` is the target offset of the last transcript record read, so WAL rows do not resend views; it also changes when `pipe.stale` is set. `gen` changes when the store re-opens the target.
- §3 server: routes call `observer.sync(id, budget)` for their sessions before they read. `walTick` (`scripts/wal-server.ts:137`) and `sessionTick` (`:101`) sync their streamed sessions before they read. `/record` (`:329`) reads the target; for a call row it returns the call record plus the Pre and Post `rec` found by `tuid`. The trash `forget` callback (`:116`) drops the reader state on trash and restore; purge also deletes the target. `shared/api.ts` gains `Pipe = {done: number; total: number; stale: string | null}`; `FirstPage` (`:78`) gains `pipe: Record<string, Pipe>` for the picked sessions, and `SessionView` gains `pipe`. The budget is 150 ms per request, shared by its sessions; the env `WAL_SYNC_BUDGET_MS` overrides it for tests only. When a streamed session's target turns stale, `/events-stream` sends `event: stale` with `{sess, reason}` once and no `reset`; `/session-stream` and `/usage-stream` carry it in `pipe.stale` of the next frame. `RecordResponse` (`:107`) keeps its shape for `ev` rows; for call rows it uses the same `{pre, post}` shape that virtual rows use today, plus `call`.
- In this phase the server runs the observer with `write: true` and no lock; Phase 5 adds the lock.
- §4 tests: existing tests pass with only these expected changes: every tool call has a call row, which replaces the MCP-only virtual row in counts and seqs; fixture sessions without a WAL now have call and turn rows in Events; a truncated or renamed WAL (`scripts/live-tail.test.ts:247-297`) gives `event: stale` and frozen rows, not `reset`; a deleted WAL leaves the rows and sends nothing; a truncated transcript (`scripts/sessions.test.ts:343-351`) gives `pipe.stale` in the next frame, not a higher `gen`. New cases: a no-WAL session gives call and turn rows and its stats equal today's; with `WAL_SYNC_BUDGET_MS=0` a first page is partial with `pipe.done < pipe.total` and a later page is complete; trash, restore and purge keep, resume and delete the target. `scripts/bench-sessions.ts:213` builds the store directly: give it an observer so `npm run check` passes.
