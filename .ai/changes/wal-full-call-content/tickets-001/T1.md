## Goal

`/record` returns the full input and response of a tool call, read from the session's transcript by tool_use_id, instead of the values that the wal-hook clamped. It adds `restored: {input?: true, response?: true}` to say which side was restored.

## Non-goals

- No change to the hook caps or to `plugins/wal-hook/`.
- No change to the target rows the observer writes (`scripts/observer.ts`): the restore is on demand in `/record` only.
- No page (web/) change; T2 and T3 own the page.
- No cache or index of transcript offsets unless a test proves it is needed.

## Context

Root cause: `plugins/wal-hook/hooks/wal-hook.mjs:29-60` clamps each string to 2000 chars (suffix `…[+N chars]`), arrays to 50 items (`…[+N items]`), depth 6 (`…[depth limit]`), and replaces a line over 96 000 chars with `{...rest, dropped: "line exceeded N chars"}` (no payload). Call rows are built from the clamped WAL at `scripts/observer.ts:446-463` (`input: pre ? pre.input : payload.tool_input`, `response: payload.tool_response ?? payload.error`).

Decisions that bind this ticket:
- Full content comes from the transcript by tool_use_id, on demand in /record, with the WAL value as fallback.
- Restore applies to every call row (MCP and all other tools) and every Pre/Post event with a tool_use_id, main and subagent transcripts, dropped lines included.
- /record adds `restored: {input?: true, response?: true}`; a side is in it only when the transcript supplied that side.

Contract (plan.md entry 1):
- New `scripts/full-call.ts`: `fullCall(dir: string, id: string, agent: string | null, tuid: string): { input?: unknown; response?: unknown; error?: boolean }`. Reads `<dir>/<id>.jsonl`, or `<dir>/<id>/subagents/agent-<agent>.jsonl` for a subagent (fall back to the main file and the other subagent files when not found). `input` is the `tool_use` (or `server_tool_use`) block's `input` in an assistant line (`message.content[]`, block `id === tuid`). `response` is the user line's `toolUseResult` for the `tool_result` block with `tool_use_id === tuid`, or that block's `content` when `is_error` is true or `toolUseResult` is absent; `error` is the `is_error` flag. A missing file or tuid gives `{}`; it never throws. Cheap pre-filter: test each line for the tuid string before `JSON.parse`. Transcripts can be tens of MB; read in chunks, as `scripts/transcripts.ts` / `scripts/discovery.ts:29` `readAt` do, not one `readFileSync` of a huge file if avoidable.
- `/record` at `scripts/wal-server.ts:629-665`: `dir` is `discovery.locate(id)` (`scripts/discovery.ts:201`, returns the folder holding `<id>.jsonl` or null). For a call row: overwrite `call.input` and `pre.payload.tool_input` with `input`; overwrite `call.response` and `post.payload.tool_response` (or `post.payload.error` when the call failed: `post.event === 'PostToolUseFailure'` or `call.err`) with `response`. Create `payload` when missing (dropped line). For a plain `ev` record (`walOf(line)`) with a `tool_use_id`: a PreToolUse restores `payload.tool_input`; a PostToolUse / PostToolUseFailure restores `payload.tool_response` / `payload.error`. The agent comes from `call.agent` or the WAL record's `agent_id`.
- `shared/api.ts:143-180`: `WalRecord`, `McpCallRecord` and `CallOnlyRecord` gain `restored?: { input?: true; response?: true }` (WalRecord has an index signature; add the key explicitly anyway so the page can read it on any RecordResponse).

Real shapes (verified on this host): an MCP `tool_response` in the WAL and `toolUseResult` in the transcript are the same content-block array, e.g. `[{"type":"text","text":"{\"id\":\"GKA-257\",...}"}]`; a Bash `toolUseResult` is `{stdout, stderr, interrupted, isImage, noOutputExpected}`, the same shape as the WAL `tool_response`. Take the fixture shapes from these.

Test harness: follow `scripts/query.test.ts` (custom `check()` helper, `startServer` from `scripts/test-server.ts`, a temp HOME with `.claude/projects/<slug>/<id>.wal.jsonl` beside `<id>.jsonl`). New file `scripts/record-full.test.ts`. Use `/events` or the index to find the seq and gen of the call row, as query.test.ts does at line ~593. Test plan: `.ai/changes/wal-full-call-content/test-plan.md`.
