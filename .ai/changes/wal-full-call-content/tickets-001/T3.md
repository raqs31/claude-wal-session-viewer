## Goal

Each Request / Response pane of the record viewer gets an Expand button that opens a full-screen dialog. An MCP response shows Structured / Text / Metadata there. A pane whose value stays clamped shows a "truncated by hook" badge.

## Non-goals

- No new display cap or truncation anywhere; Copy always takes the full value.
- No change to `/record` or `shared/api.ts` (T1) or the helpers (T2).
- No new dependency.

## Context

Decisions that bind this ticket:
- Per-pane Expand opens a full-screen dialog with the JSON/YAML/Raw format switch and a Copy of the full value in the active format; Escape closes it.
- An MCP call's Response shows the non-empty sections of `mcpSections` (T2, `web/src/lib/sections.ts`), each with its own Copy; empty sections are hidden.
- The inline pane also parses the restored JSON (it already does through `viewNodes` → `normalize` once /record returns the full value; keep that path).
- Badge "truncated by hook" when `clampBadge(v, restored)` (T2) is true. `restored` is the `restored?: {input?: true; response?: true}` that T1 adds to every RecordResponse: Request pane uses `restored.input`, Response/Error pane `restored.response`, the single "Record" pane of a plain event uses the side of its event (PreToolUse → input, Post* → response).

Code:
- `web/src/components/RecordViewer.tsx`: `Pane` (line 8) holds the Copy button (`copyText`, `web/src/lib/tree.ts:71`); `Split` (line 41) builds the Request and Response panes; `RecordViewer` (end) picks Split or a single Record pane. Format comes from `EventsTab.tsx` (`FORMAT_LABEL`, line 15) as a prop; the dialog keeps its own format state, starting from the pane's format, with the same three options (`FORMATS` in tree.ts).
- MCP call: `rec.call.mcp === true`.
- Dialog pattern: native `<dialog>` with `showModal()` as `web/src/components/charts/UPlot.tsx:~142` does (Escape closes through the native cancel event; follow its biome-ignore pattern). Styles for the overlay are in `web/src/styles.css` (search for the UPlot overlay rules added in commit 52009a6) — reuse the look.
- Large values: a big record's tree is ~10^5 nodes (RecordViewer comment). Build the dialog content only while it is open; build Copy text on click only, as Pane does.
- README.md: add one or two sentences on the Expand view and the badge where README describes the record viewer / Events tab.

Depends on T1 (the `restored` type) and T2 (the helpers); read their Results first (`ticket.py show … --with-deps`).

Decisions:
- Badge rule: `clampBadge(v, restored) || (!restored && wal has a top-level 'dropped' key)`. `wal` is `pre` for Request, `post` for Response/Error. This is the PO's added rule. For the plain Record pane the whole record goes to `clampBadge`, which already checks top-level `dropped`.
- `paneBadge` takes `wal?: object` so sections.ts stays free of the API types.
- The dialog's Text section is a `<pre>` of the text blocks joined by a blank line, and its Copy gives that same string, whatever the format. Structured and Metadata follow the dialog's format. A single structured item shows as itself, several as an array.
- The MCP split applies to the response side whenever `call.mcp === true`, an Error pane included. The inline pane keeps the plain tree.
- The dialog has no backdrop-click close (the ticket names only Escape), so it needs no biome-ignore. It has a Close button. It is portalled into the closest `.viz-root` for the theme variables, as UPlot does.
Open: none. The dialog markup has no automated test; the badge decision does.
