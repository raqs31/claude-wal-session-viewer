## Goal

Two pure page helpers: `mcpSections()` splits an MCP response into Structured, Text and Metadata, and `clampBadge()` decides the "truncated by hook" badge.

## Non-goals

- No UI or component change; T3 uses these helpers.
- No change to `web/src/lib/normalize.ts` or `web/src/lib/tree.ts`.

## Context

Decisions that bind this ticket:
- An MCP response shows Structured / Text / Metadata; an empty section is hidden (absent from the result).
- The "truncated by hook" badge shows only when the value was not restored by /record and a clamp marker is present. A restored value that contains marker text gets no badge.

Contract (plan.md entry 2), new file `web/src/lib/sections.ts`:
- `mcpSections(v: unknown): { structured?: unknown[]; text?: string[]; meta?: Record<string, unknown> }`. Input is the raw response as /record returns it: a content-block array (`[{type:'text', text:'…'}, {type:'image', …}]`), an object (e.g. `{content: [...], isError: true, _meta: {...}, structuredContent: {...}}`), or a string. Text blocks whose text parses as JSON go to `structured` (parse with `normalize` from `web/src/lib/normalize.ts`, which returns a non-string for JSON text); other text blocks go to `text`; `structuredContent` goes to `structured`; every non-text block and every other key (`isError`, `_meta`, …) goes to `meta` (non-text blocks under a key such as `blocks`). A bare string is one text block. An empty section is absent.
- `clampBadge(v: unknown, restored: boolean): boolean`: false when `restored`; else true when any string anywhere in `v` ends with `…[+N chars]`, equals `…[+N items]` or `…[depth limit]`, or `v` is an object with a top-level `dropped` key. The markers come from `plugins/wal-hook/hooks/wal-hook.mjs:54-60`; `scripts/observer.ts:40` has `CLAMP_RE = /…\[\+\d+ chars\]$/`.

Test style: `node --test` with `node:test` and `node:assert`, as `web/src/lib/tree.test.ts` does. Test plan: `.ai/changes/wal-full-call-content/test-plan.md`.

- When: clampBadge() is called with each value and its restored flag
- Then: it is true for each marker value that is not restored, and false for the full value and for the restored value
- Check: `node --test web/src/lib/sections.test.ts`
