## Goal

The table headers drive the sort and the `Order` button is gone. Date and Time become one Datetime column. Input and Total+In are new columns.

## Non-goals

- No sort by Event, Tool or Session; no ascending datetime order.
- No sort under Live or Tail, and no live insertion of rows into a sorted view.
- No sort saved across reloads or put in the URL.
- No README change (T11).

## Context

Source: plan.md Phase 3, items 2-4, and "Critical Implementation Details". Read `web/src/lib/sort.ts` (T9) for the contract: `SortKey`, `Sort = { key; dir: 'asc' | 'desc' } | null`, `next(sort, key)`, `sortParams(sort)`, `canSort(follow, view)`. `Row.inp?: number` is in `shared/api.ts` (T1).

State wiring (`web/src/App.tsx`, `web/src/useEvents.ts`):
- Replace `order`/`Order` with `sort: Sort` (`App.tsx:37`, props at `:133-134`; `Order` type at `useEvents.ts:8`). Remove the `Order` type. Not stored: a reload comes back in datetime order.
- `useEvents(filters, view, ids, sort)` (`useEvents.ts:68`): `params` (`:62`, `sort=tokens` at `:64`) adds `sortParams(sort)`. It skips the `EventSource` while the sort is not null (`:181-182`). It re-queries when the sort changes (effect deps `:318-321`). The `order === 'time'` guards (`:174-175`, `:289`, `:294`) become `sort === null`.
- The `tokens` frame handler (`useEvents.ts:215`) spreads the patch, so `inp` applies; keep it.

Toolbar (`web/src/components/EventsTab.tsx`):
- Remove `button#order` (`:210-219`). Props trade `order`/`setOrder` (`:44-45`) for `sort`/`setSort`.
- Turning Live on (`:192-202`), or switching View to Tail (`:208`), sets the sort to `null` in the same handler. If not, one render opens an `EventSource` with a sort, the server returns 400, and the stream dot shows an error.
- A non-null sort still forces the table branch (`:233`) and shows the stream as `paused` (`:224`).
- Pass `sort`, `setSort` and `canSort(follow, view)` to `EventTable`.

Table (`web/src/components/EventTable.tsx`, header at `:96-108`; `web/src/components/EventRow.tsx`):
- Columns in order: Datetime (~200px), Event, Tool, Duration, Input, Output, Result, Total, Total+In, Session.
- The six sortable headers (Duration→`dur`, Input→`inp`, Output→`out`, Result→`res`, Total→`tot`, Total+In→`all`) are buttons calling `setSort(next(sort, key))`. The active one shows `▼` (desc) or `▲` (asc) and sets `aria-sort` on its `<th>`.
- When `canSort` is false they are inert and dimmed, with the tooltip "Turn off Live and switch to Table to sort". Style in `web/src/styles.css`.
- The Datetime header resets the sort to null.
- `EventRow` (`:58-59`): one Datetime cell, `fmtDate` and `fmtTime` (`web/src/lib/format.ts:2,6`) joined by a space: `YYYY-MM-DD HH:MM:SS.mmm`. Input from `r.inp` with the `Tokens` cell (`:21`, `:87-89`). Total+In is `inp + out + res` when `out` is present (missing parts count as 0), and `—` otherwise.
- `EventTable` contract: props `sort`, `setSort` and `canSort`.

The verify greps must find no whole-word `Order` and no `sort=tokens` in `web/src`. The SSE event name `tokens` (`es.addEventListener('tokens'`) stays.
