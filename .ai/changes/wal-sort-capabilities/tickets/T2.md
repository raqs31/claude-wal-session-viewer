## Goal

Every `tok` the observer join emits carries `inp`: the fresh input tokens of the reply behind the call or Stop.

## Non-goals

- No change to `out` or `res` values.
- No change to the index, the server or the web.
- No forced re-index; `/rebuild` (`scripts/observer.ts:954`) is the path that fills old sessions.

## Context

Source: plan.md Phase 1, item 1. Read `scripts/target.ts:63-64` for the T1 contract (`inp?: number` on both `tok` variants).

- Fresh input = `input + cacheWrite5m + cacheWrite1h` of the reply's `UsageRecord` (`scripts/transcripts.ts:39`, fields at `:75-76`). Not `cacheRead`.
- `callTok` (`scripts/observer.ts:728`): sets `inp` with `share(fresh, reply.calls.map((c) => c.size), at)`, the same weights as `out` (`share` at `scripts/observer.ts:167`; its parts add up to the total). Every return path that yields a `tok` carries `inp`.
- `stopOut` (`scripts/observer.ts:757`): returns `{ out, inp } | null` instead of `number | null`. A Stop gets the full fresh input of its reply.
- `joinTokens` (`scripts/observer.ts:773`): puts `inp` on the Stop `tok` (`{ k: 'tok', woff, out, inp }`).
- Contract: every `tok` the join emits carries `inp: number`.

Tests in `scripts/tokens.test.ts`, following the existing cases (e.g. `:100`, `:108`, `:199`). One assertion each:
- A single call gets `inp` = input + cache writes.
- Two parallel calls split `inp` by input size, and the parts add up to the reply's fresh input.
- A Stop gets the full `inp`.
Update existing assertions that compare whole `tok` records so they include `inp`.
