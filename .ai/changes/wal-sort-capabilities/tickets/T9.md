## Goal

A pure module holds the web sort rules (click cycle, query params, when sort is allowed), testable with `node --test` without a DOM.

## Non-goals

- No wiring into components or hooks (T10).
- No sort persistence across reloads, no URL state.

## Context

Source: plan.md Phase 3, item 1. Server params from T5 (`scripts/wal-index.ts`, `query()`): `sort ∈ {inp,out,res,tot,all,dur}`, `dir ∈ {asc,desc}`.

Contract (plan.md):
- `type SortKey = 'inp' | 'out' | 'res' | 'tot' | 'all' | 'dur'`
- `type Sort = { key: SortKey; dir: 'asc' | 'desc' } | null`
- `next(sort: Sort, key: SortKey): Sort`
- `sortParams(sort: Sort): [string, string][]`
- `canSort(follow: boolean, view: View): boolean`

Rules:
- The click cycle: `null`, then `{key, 'desc'}`, then `{key, 'asc'}`, then `null`. A click on a different key starts at `desc`.
- `sortParams(null)` is `[]`; a sort gives `[['sort', key], ['dir', dir]]`.
- `canSort` is true only when Live is off and View = Table.
- `View` is `web/src/useEvents.ts:6`. Import it with `import type` so the test does not load React. Copy the test layout from `web/src/lib/params.test.ts` (`node:test`, `node:assert/strict`).

Tests in `web/src/lib/sort.test.ts`, one assertion each: the full click cycle on one key; a click on a new key while another is active; `sortParams` for `null` and for a sort; `canSort` for all 4 Live/View combinations.
