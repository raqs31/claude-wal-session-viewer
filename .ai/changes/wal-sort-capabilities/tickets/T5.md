## Goal

`/events` sorts by any of six keys in either direction: `sort=<key>&dir=<asc|desc>`, with a cursor that pages through every row in one order. `sort=tokens` is gone.

## Non-goals

- No sort by Event, Tool or Session, and no ascending datetime order.
- No precomputed sort index: the per-page full scan stays, as in `byTokens`.
- No change to `min_tok`, `max_tok`, `notok`: they still use Total.
- No change to `scripts/wal-server.ts` or `scripts/bench.ts` (T6, T7).

## Context

Source: plan.md Phase 2, item 1, and "Critical Implementation Details". Builds on T3 (`IndexEntry.inp` in `scripts/wal-index.ts:45`).

Turn `byTokens` (`scripts/wal-index.ts:634`, key type `TokKey` `:624`, comparator `ahead` `:631`) into a generic `byKey` that takes a key function and a direction.
- Keys: `inp`: `e.inp`; `out`: `e.out`; `res`: `e.res`; `tot`: `tokensOf(e)` (`:391`), Out + Res; `all`: `inp + out + res`, null until `out` lands, a missing part counts as 0; `dur`: `e.dur`.
- Missing values sort last in both directions. A row with no value for the key stays after every row with a value, for `asc` too. Today a missing Total sorts as -1; that no longer works for `asc`.
- Ties between rows keep the current time tie-break (`cmp`, `:569`) in both directions.
- The `lazy` `q` path and the `first` counts stay as they are.
- Keep the key function a plain field read: each page is one full scan, guarded by the bench at 300 ms.
- `query()` (`:699`, dispatch at `:708`) dispatches on a valid `sort` key. An unknown `sort`, or an unknown `dir`, falls back to time order. Remove the `sort=tokens` branch.

Contract (plan.md):
- Query params: `sort ∈ {inp,out,res,tot,all,dur}` and `dir ∈ {asc,desc}`. `desc` is the default.
- The cursor is `before=<v>.<t>.<sess>.<seq>`, where `<v>` is the key value, or `n` when the row has no value.
- The regex replaces `TOK_CURSOR` (`:586`): `/^(-?\d+|n)\.(-?\d+)\.([0-9a-f-]{36})\.(\d+)$/`.
- `next` is null on the last page.

Tests in `scripts/query.test.ts`: rewrite the sort cases at `:844-864` for `sort=tot` (helper `pageAll` already used there). New cases, one assertion each:
- Each key in both directions: paging over all rows (small `limit`) gives the same order as a full sort.
- Rows with no value come last, for `asc` too (the cursor crosses from a value into `n`).
- `q` with paging still gives full, ordered pages.
- An unknown `sort` gives time order.
